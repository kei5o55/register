## RejiStella（レジアプリケーション）

同人即売会イベント等で使用するためのレジ機能＋頒布分析機能を実装したレジアプリ。

単純なレジ機能にとどまらず、分析機能を追加することで長期的な創作活動の支援を目指しています。


**DEMO:** https://register-3k2l.vercel.app/
（ブラウザ上から実際に操作できます。初回起動時にサンプルデータを挿入しています）

**（IndexedDBを使用しているため、過去のデータが残っている場合があります。
サンプルデータが表示されない場合、DevToolsの
Application→Storage→Clear site data
からサイトデータを削除した後再リロードしてください。）**

バックエンド領域への理解を深めるため、  
Dockerを用いたRails+DB環境の構築や、簡易的なAPIサーバの作成にも取り組みました。
https://github.com/kei5o55/cashier-server

## 開発背景

同人頒布イベントに参加するにあたって、印刷数の想定・在庫管理・売上記録・撤収判断などを手作業もしくは憶測で行うことが多く、レジと記録・分析を同時に扱えるツールが少ないという課題を感じました。

そこで、イベント現場で実際に使えるレジアプリとしてRejiStellaを開発しています。

単品・セット頒布に対応しており，イベント単位で売り上げ・頒布数を管理し，グラフによる可視化機能を実装しています

頒布データの時間推移からイベント撤退時間の目安を立てたり、頒布数から増刷や新刊部数の参考にしたりと、単純なレジ機能にとどまらず、創作活動に役立つ分析機能の実装を目指しています。


## 制作目的
- モダンな Web 技術（TypeScript/React）を用いた 実践的なアプリケーション開発経験の習得
- 同人即売会の現場を支えるツールの制作を通じて，自身および他者の創作活動の支援につながるプロダクトの開発を目指す

## 設計面の工夫した点
- 集計ロジックと表示ロジックを分離
  - 将来的な拡張性を確保
  - ```scr/components```と```src/logic```とで分離
  - App.tsxは主にコンポーネント切り替えを担当、componentsには表示する画面をまとめることで分かりやすいディレクトリ構成を図っています
- イベント単位での売上データ設計
  - 売上ごとにEventIdを紐づけ、集計しやすいデータ型としています。
- バンドル内頒布物を展開して在庫・集計に反映
```
export type BundleLine = {
  itemId: string;
  quantity: number;
};

export type Bundle = {// バンドル商品
  id: string;//バンドルごとの一意なID
  name: string;//バンドル名
  lines: BundleLine[]; //中身（アイテムIDと個数）
  price: number;// バンドル価格
  tags?: Tags;//タグ（任意）
};
```
 最初はバンドルは頒布物を複数選択して制作（idと値段のみ）みたいな単純な設計だったが、このままだと在庫数の計算や集計時にセット内の頒布物がどれだけ売れたのかが分からない　といった問題点がありました。
 
 バンドル内に配列として複数のアイテムを保存できるような型設計とすることで単品・セットをまたいだ集計・管理を両立しました。
- 再利用可能なコンポーネント設計
  - **HistoryScreen・SalesChart・TagEditor** の複数機能をまたいで使用する機能コンポーネントを分離し作成することでReactの再利用性を有効活用
- ISO形式で日時を保存し，時間別の集計に対応



- 現場での長期的な運用を想定し、イベントごとに頒布物の設定・売上の集計

    
## 使用技術
- **TypeScript**
  - 静的型付けによる安全性の高い実装を行い
    バグの抑制および保守性・拡張性を意識した設計を実施
  - 商品名（string）、単価（number）、数量（number）など、レジアプリ特有の多様な入力値を厳密な型定義で管理することで、型不一致による不具合を未然に防いでいます

- **React**
  - コンポーネント指向に基づく画面構成を採用し，UIの再利用性と拡張性を考慮した実装
  - 当初はNext.js等のフルスタックフレームワークの導入も検討しましたが、現段階での本アプリが求める「オフラインファースト」および「現場でのサクサクした画面切り替え（SPA）」という要件において、フレームワークの使用はオーバーエンジニアリングになると判断。

- **Recharts**
  - 売上データを棒グラフとして可視化
  - 日別・商品別などの集計結果を直感的に確認できるUIを実装

- **IndexedDB**
  - オフライン環境でもレジ機能が停止しないよう、IndexedDB を用いて売上データを端末内に永続化
  - 保存したデータを用いた集計およびグラフ描画を実装
  - 将来的にはサーバサイドDBへの同期を行い、複数端末での売上管理・分析が可能な構成へ拡張が出来たら面白いのではないかとも考えています。
 
- **PWA**
  - PWAとしてスマートフォン / タブレットにインストールが可能
  - 簡単に起動でき、オフラインでも正常に動作する設計
 
 
イベント会場では通信環境が不安定になることが考えられるため、
レジ操作がネットワークに依存しない
オフラインファースト設計を採用しました。

## 設計・マルチデバイスへのこだわり
スマートフォンやPCなど機種を問わず利用できるWebアプリケーションとして開発することで、
より多くの人が環境に縛られず、気軽に扱える設計を目指しています。

私自身、当初**Surface Pro**を用いて開発を行っており、はじめは自分用のsurface(pc)で動くアプリとして開発していましたが、スマホ・タブレットなど端末種類を問わずに使用できることがwebアプリの利点であると感じ、現在本アプリは特定のOSや専用のレジ端末に依存しない「環境に縛られないレジ」を目指しています。

Webアプリケーション（PWA）として設計したことで、以下のような柔軟性を実現しました。

- **PC（Surface等）:** 大画面を活かした設営や、キーボードとマウスによる腰を据えたイベント前後のデータ分析ダッシュボードとしての運用
- **タブレット / スマホ:** スペースの限られた机上でのコンパクトなレジ端末としての運用
- **その他:** ブラウザが動く環境であれば、型落ちの端末であってもあらゆるデバイスが瞬時にレジ機能を持つ端末に変貌

「手持ちの機材、どれでもすぐにレジになる」という手軽さを提供することで、出展者が機材調達のコストや環境の制約に縛られることなく、誰もが気軽に、かつ安心して自身の創作活動の現場を支えられる設計を追求しています。
また、将来的にユーザごとのデータ同期などが可能となれば、「家では作業用pcでデータ確認・登録、現場ではタブレットで運用」のように端末ごとの利点を生かした運用が可能になると考えています。

- よかった点
  - 隣スペースの方との会話のきっかけになった
  - 基本的なレジ機能には問題がなく，わかりやすくスムーズに運用できた
    - 特に、サークル側から値札などをいちいち確認することが難しく、会計時に画面に合計金額が表示されるのは凄く便利だと感じた。
  - 分析グラフ化機能が思ったより役立った
    - 視覚的に頒布数が分かりやすい
    - 時間別グラフも山を作るような形状となっており、イベントごとに差が発生するのか興味が出た＋ちゃんと分析として機能していることが分かった。
  - pwa化しタブレットにインストールした運用がとてもやりやすかった
     - オフラインファースト設計が活きた

- 気になった点
  - 待機画面がほしい
    - 一度画面を閉じた際，会計時にいちいち開くのが手間
    - かといってレジ画面を出しっぱなしにするのも見栄えが良くないと感じた
    - イベントごとに設定できる待機画面などを作りたい→ [#25](https://github.com/kei5o55/register/issues/25)において待機画面の実装を検討
    - 設営の話ではあるが，お客さんから見える方にもモニターを設置し，サークルアピール画像などを表示→会計時はレジ画面を表示できるようにすることで合計金額が相手からもわかりやすく，見栄えも良いと感じた
  - 会計後に追加で欲しいってなることがある（１売り上げに入らなくなる）
    - 後から紐づけられるようにする？
    - 機能面では特に問題がないが，売上件数など一人に対して２件になってしまい，分析に誤差が出るのが気になった
    - 衝動買いが発生しやすい即売会の現場では特に重要な点だと感じた．要検討
  - 売上履歴の画面が分かりづらい
    - 各売り上げがどのイベントに紐づいているのか，詳細な情報が少ない
  - 性別や年齢層を入力できるとより分析に活かせるかも
    - 自分の作品に興味を持ってくれた人と実際に対面できることが即売イベントの良いところであると考えており、そういった機会で自分の創作物がどのような層から求められているのかを他者目線から分析可能とすることで，自分の今後の創作に活かせると感じた
  - UIがシンプルでぱっと見たときにボタンが分かりづらかった
